# Metronome (`HX_CLICK=1`, `tools/patch_click.py`, `src/sharc/click.asm`, `tools/features/metronome.py`, `src/m4/metronome.s`)

A click-track block, Volume/Pan > Metronome, with a tempo-synced Time and its own DSP kernel. Status tags as in [conventions.md](../conventions.md).

- A mono effect, Volume/Pan > Metronome > Metronome (preset ID 181, DSP cost 50; modulation, not delay, so no trails), on a copy of the mono effect host whose member is primitive `0x0128` (registry `0x200050`; NAM has `0x9c75`). Knobs: Time (1/4 by default, synced), Level (dB, −14 by default), Accent (Off, 2..12: a 2 kHz downbeat every n beats), Thru (On passes the input). Its map is Simple Delay's sync chain without the `0x2d` node: the clamp's output is the kernel's pid 5.

When on, the harness feeds it (L+R)/2 and sends its output to both sides, so after stereo blocks the signal is mono from there on: −20 dB on the left alone came out −26 dB on both sides, the same as stock Mono Gain. Bypassed, the harness passes L and R apart [verified offline: the map of `HD2_AppFxHarnessMono`, blob 283]. To keep a stereo rig stereo, put it before the stereo delays and reverbs, or alone on path B with Thru Off: then only the click joins at the merge's Mixer, and the right side stayed below −95 dB (with Thru On, the mono sum leaked to the right at −38.6 dB). The Mixer's centre pan puts path A 3 dB down (−23 dB), and a bypassed block on path B, the Metronome as stock Mono Gain, passes the guitar to the Mixer again at B Level: with this preset's B Level of −9.6 dB the left rose to −20.5 dB, the same from 220 Hz to 3 kHz. Set up through the unit's own screens [verified on unit, RAM run 2026-11-22, MD5 `94766f98…`]: the Mixer is selectable where the paths merge, and holding Knob 3 (B Level) opens Controller Assign for B Level; with FS1 as its controller (Latch), Min Value goes down to −60.0 dB. - **Its look** [verified offline; on unit, RAM run 2026-11-22, MD5 `94766f98…`: teal in the signal flow, lit when on and dim when off, the metronome icon; a preset saved with the Looper build loads, dim teal when off]: two categories decide it. (1) The signal flow's slot picture is `table[slot category * 6 + state]` (`0x28e3abdc`; set at `0x28dc992c`), the slot category being the *browser* category in the block's info (`0x28e0fe94` → `0x28e0fafc`: the block record's halfword +0x14 to info +0xc; the info's bytes 1..4 are the preset model ID). It is written to the UI's slot model at `+0x37` at `0x28dd3046` (`ldrb.w r2, [sp, #0x10]; strb.w r2, [r3, #0x37]`) and at `0x28dd2bfe` (in `0x28dd2b48`, a path's redraw); the other writers move it between slots. Volume/Pan (`0x10`) has `Block_FXLoopThumb`: teal, with the block's own on/off. Looper (`0x12`) takes its own path (`0x28dc994a`): the grey `Block_LooperThumb` pictures with the looper's on/off, so under Looper the Metronome showed dim grey whether on or off [verified on unit, `d436279a…`]. (2) The *block* category (0..`0x19`, records at `0x28e2815c`: name, short name, colour, dim colour, icon, off icon; getter `0x28d9e01c`) is not Table 2's byte 21 (which mirrors it) but the model's Entry 3 meta `category` (key `0x35`), read only by `0x28dff824`, which maps its string index (`modulation` `0xc6` → 7, `looper` `0xf83` → `0x17`, …) and gives `0x19` (Unknown) to a model without one: only the app, harness, mic and null models (34). The Metronome has no `category`, and `tools/features/metronome.py` makes `0x19` Metronome: teal, Icon_Tempo, and a dimmed copy as its off icon.

  - The footswitch assign `0x28dd8478` (called by `0x28dd99c0`, which the turn calls with the footswitch and block) switches on the *block* category from `0x28e0f064` (the getter that ends in `0x28dff824`; its only other caller is `0x28d9013a`): None `0x18` and Unknown `0x19` go to `0x28dd8506`, which clears the footswitch's slot and returns its non-negative result, so the turn "succeeds" and redraws None.   - A block added from the browser or pasted (message 5/`0xa`, `0x28d94ec8`), on a slot with no footswitch or controller record (`0x28dd4c08` → `0x28dd448c` → `0x28dd46a0`; **[hypothesis]** a model change keeps its slot's), goes through a switch on its browser category, 8..`0x11` (`0x28d952d0`): Wah `0xa`, Volume/Pan `0x10` and Pitch `8`'s Pitch Wham and Poly Wham (preset IDs 182, 184, 575, 577) go on FS5 (`0x28dd99c0(…, 4, block, 1)`, beside the blocks already there), and Wah is switched off, Volume/Pan on (`0x28e045a0`): an expression pedal's toe switch flips between them. Every Volume/Pan model goes, Gain too [verified on unit: Gain and Volume Pedal took FS5]. `metronome_add_cat` gives preset ID 181 Modulation's `5`, outside the switch, so the Metronome stays off FS5 [verified on unit: Bypass Assign reads None, and the preset gains no footswitch or controller]. Send/Return `0x11` rebuilds the availability table (`0x28e12280`).
  - The EXP pedal is not that switch: `0x28de0344`, in the controller handler `0x28ddff74` for the same message, puts param 0 on EXP 1 (Wah, Pitch) or EXP 2 (Volume/Pan) only when `0x28e110c0` finds its name is Pedal (`0xcc`) or Position (`0x49`): Volume Pedal and Pan, not Gain, Stereo Width, Stereo Imager or the Metronome, whose param 0 is Time [verified on unit: Volume Pedal took EXP 2, Gain and the Metronome nothing; the Lower Knob from a Volume Pedal to the Metronome drops EXP 2].
  - The Lower Knob changes a block's model and keeps its slot's footswitch record, so a Metronome reached from a Volume/Pan model that went on FS5 stays on FS5, as any model would [verified on unit].
- The kernel counts samples since the last beat (100 ms .. 8 s, from pid 5 x 48000) and plays a 1 kHz sine (2 kHz on a downbeat) at half scale x Level, 6 ms decay. A new Time puts the next beat a new beat after the last. Its 142 instructions sit right under NAM's cold code, above NAM's three slots in Block 3 (`patch_click.pm_base`, from `nam_multi.Layout`); all its state is in its own instance words, DM(20..26) and DM(100..119).
