# Tap command (`HX_CC_TAP=1`, `tools/features/tap_command.py`, `src/m4/tap_command.s`)

A Tap command in the Command Center for FS1..FS5 (issue #108): a Stomp footswitch whose slot holds it taps the tempo, and its ring blinks the tempo as the TAP ring does. The Command Center is saved per preset, so tap lives only in the presets that want it. Status tags as in [conventions.md](../conventions.md). The Command Center itself: [m4/command-center.md](../m4/command-center.md).

- **Decisions** (2026-11-17): the command is stored as type 9, the Helix's CV Out, never offered on the HX Stomp but complete in every table, so a preset holding it opens on stock firmware with a command that does nothing (a new type 22 would have read past the end of stock's tables). The ring blinks with the tempo. The Home screen label stays stock: the node's name, Tap, as stock labels every command. HX Edit's view of a type-9 slot is checked on the unit.
- **Data** [verified offline]: the FS slots' place counts (words `0x28e3c5f4 + 4s`, s = 6..10) go from 10 to 11; type 9's name (`0x28e3c670`) becomes `Tap`; its knob count (`0x28e3c6e1`) goes from 2 to 1, so only the Command knob shows.
- **HX Stomp XL** [verified offline]: the same Tap command is offered across XL's eight Command Center footswitch slots; its XL handler uses the six ring-capable Stomp switches and treats the dedicated TAP ring separately. The command tables and 14 XL hook sites are stock-guarded. XL Tap Command, including its interaction with Tap LED Color, has not yet been verified on-unit.
- **The Command knob** [verified offline]: the view's turn handler (`0x28dbd6a2..0x28dbd736`) stops a right turn on an FS slot at Looper (`cmp r0, #0x10` at `0x28dbd72c`) and a left turn at None, before it calls the step. So Tap goes inside the list, after Hotkey (place 7): None, MIDI CC, CC Toggle, Bank/PC, Note On, MMC, Hotkey, Tap, Preset, Snapshot, Looper. `tc_step` (owning the call `0x28dbd6bc`) walks that list one place per call, as the stock step does whatever the turn's size, and treats a type not on it as None, as stock does; Instant and EXP slots go to the stock step. `tc_choice` (owning `0x28dbd366`, `0x28dbd4d0`, `0x28dbd9fa`) gives Tap place 7 on an FS slot and moves stock's Preset, Snapshot and Looper (7..9) one place up; the other two calls are paste checks (`0` refuses), so Tap pastes onto FS slots only.
- **The footswitch node** [verified on unit]: in `command-ctr-tap-1` a Tap slot was stored (its ring blinked) but a press never tapped. A debug image (`-2`, `tc_fire` writing a call count into FS2's ring colour) showed `tc_fire` never ran: the node insert names a new command node through `0x28dd568c(node, type)`, which refuses type 9, so no node joined the footswitch's list ([m4/command-center.md](../m4/command-center.md)). `tc_node` owns both its calls (`0x28dd88d2`, `0x28dd8a68`): type 9's node is named `Tap` (stock's strcpy `0x28daad94` to node + 0x24) and accepted; every other type is named as stock. So a footswitch with no block reads Tap on Home, as one with a Hotkey reads Hotkey; stock firmware makes no node for it.
- **A press** [verified on unit]: `tc_fire` owns the stomp toggle's fire call `0x28dd1342` (every command but Looper's and Snapshot's Behavior-1 path). For type 9 it calls the tap core `0x28d9bfa8` through its entry, so bpm's `chain_entry` there still runs, then sets the beat's period; every other type goes on to the stock fire `0x28de5cd4` with its arguments. Snapshot recall's fire `0x28de36b6` stays stock, and does nothing for type 9, so a snapshot change never taps. The footswitch's command state still flips on each press, as for any command.
- **The ring** [verified offline]: the stock beat ([m4/tempo-and-leds.md](../m4/tempo-and-leds.md)) turns only while FS3 is TAP, lights only LED 2, and its period setter `0x28d9bef8` also puts LED 2 in blink mode. So:
  - `tc_running` owns the beat's two "is FS3 TAP" reads (`0x28d9be3a`, `0x28d9be4c`): while FS3 is not TAP and a Tap ring is active, it hands back a state whose FS3 byte reads TAP, so the beat keeps time.
  - `tc_on` owns the on-turn's FS3 check `0x28d9be92`: it lights each active ring (colour, then mode 1), then hands back the real state, so FS3's own lighting runs only when FS3 is TAP.
  - `tc_off` owns the off-turn's `0x28db8260(2, 0)` at `0x28d9beba`: LED 2 off only when FS3 is TAP, then each active ring off.
  - `tc_refresh` owns the LED refresh's functions read `0x28dd0b70` (once per ring). While FS3 is not TAP and a ring is active, it (and `tc_fire`) writes the period (`0x281ccc44`, 60000 / BPM in whole ms, from setting 15 or 16 as Tempo Select picks, without VFP) and the enable byte `0x281ccc48`, when Tap Tempo LED (setting 26) is On, and clears the enable when it is Off, as the TAP case does (`0x28d9bf8c`); unset leaves both, as stock. FS3 TAP keeps the stock period path.
  - `tc_setting` owns a tempo setting's change looking for a TAP footswitch (`0x28dd276c`, the `0x28d9607c()` read of its loop, [m4/tempo-and-leds.md](../m4/tempo-and-leds.md)) and runs `tc_tempo` first, so a Tap ring's beat follows a new BPM, from external MIDI clock too, as stock resets only a TAP ring's.
  - An active ring: FS1..FS3 whose function byte is 2 (Stomp) and whose slot's type is 9. Preset, Snapshot and Scroll modes rewrite the function bytes, so only Stomp switches blink.
  - Colour: stock red `[0x28e280b0]`, blue `[0x28e280ac]` on external clock. With Tap LED Color in the build, its `tap_led` for the first ring of a turn when FS3 is not TAP (Rainbow and Random move on once a turn), else its `tap_led_again`. With FS3 TAP too, FS3's own turn moves the colour on after the Tap rings are lit, so they show the step before FS3's. [hypothesis] Between beat turns the stock refresh may repaint a Tap ring by its command state; the next turn sets it again.
- **Tests**: `tests/test_tap_command.py` (handlers in unicorn, the stock tables and code they rely on, including type 9 inert on stock and the stock knob step and places run in unicorn, the build, with and without Tap LED Color, and alongside every feature).
- **On the unit** [verified on unit, 2026-11-17, `command-ctr-tap-3`, .hxf MD5 `1a0485e2…`, a RAM run with HX_CC_TAP, HX_TAP_COLOR (Random), HX_BPM, HX_LONG_PRESS, HX_CLICK, HX_SCREEN_MIRROR, HX_USB_INPUT]: the Command knob on Footswitch 1 reads None, MIDI CC, CC Togl, BankPC, NoteOn, MMC, Hotkey, Tap, Preset, Snpsht, Looper and stops at Looper; on Tap only the Command knob (and the stock Customize) shows. FS1 on Tap: six presses 0.67 s apart set the BPM to 90 (it read 120), Home labels FS1 Tap, and its ring blinks with FS3's TAP ring (turns about 0.33 s apart) in the colour FS3 had the turn before. FS3 Function Stomp 3 with Tap: six presses 0.6 s apart set 100 BPM, and with no TAP footswitch left both Tap rings blink together, the same colour, a turn about 0.3 s. One knob click does not always move the Command knob or FS3 Function a place (the devtest's dial reads after each click).
- **By hand on `-3`** (2026-11-17): a 2 s hold of FS1 or FS3 (Long press on, default holds) leaves the BPM as it was, and short presses still tap; taps at a tempo of his own follow as the TAP switch does. Tap Tempo LED Off did not stop the Tap rings blinking: the refresh set the beat going but never stopped it, so `tc_tempo` now clears the enable on Off.
- **HX Edit** [verified on unit]: HX Edit 3.80 has no Command Center for the HX Stomp (only Edit and Bypass/Controller Assign), so it never shows a slot. Whether a preset export or a backup and restore keeps a Tap slot is not checked.
- **The label stays lit** [verified on unit, `-6`]: the stomp toggle flips the command node's state (`[node + 0x20]`) before the fire, and the label and ring show it, so a Tap label went lit and unlit on each tap. `tc_lit(k)` (`0x28dd7218(0x28d96084(), k)`, the node, then state 1) runs after each tap in `tc_fire` and for every Stomp footswitch with a Tap command in `tc_refresh`, which also covers a freshly assigned one.
- **By hand on `-5` and `-6`** (2026-11-17; `-6` MD5 `3350aa33…`, HX_CC_TAP, HX_TAP_COLOR, HX_BPM, HX_LONG_PRESS, HX_CLICK, HX_PRESET_COLOR, HX_SCREEN_MIRROR, HX_USB_INPUT): Displays reads LED Ring Brightness, Tap LED Color, empty, with Preset LED and This Preset on page 2 and no Tap Tempo LED; Tap LED Color kept its colour on the first boot with Tap Tempo LED On; Tap LED Color Off stops the TAP ring and the Tap rings at once in Global Settings, a colour starts them again in time; a Tap label stays lit as you tap.
- **External MIDI clock** (2026-11-17, a RAM run of next `b5ee7f8`, MD5 `4f604e3f…`, clock over USB from `mido`): with FS3 TAP and FS1 Tap, both rings turn blue and follow the clock (90, then 140 BPM), and go back when it stops. With FS3 Stomp 3, the Tap ring turned blue but kept the preset's 95 BPM through 60 and 180: the clock's tempo changes reset only a TAP ring's beat. `tc_setting` fixes it [verified on unit]: on `tap-clock` (MD5 `0d8ecea6…`, same features) the Tap ring, blue, follows 60 then 180 BPM with FS3 Stomp 3. Not checked: the period after a preset change when FS3 is not TAP.
- **Not checked, and dropped** (2026-11-17): a saved Tap preset on stock firmware, a preset export through HX Edit, a `tools/hx_devtest.py` case.
